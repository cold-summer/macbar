# 故障排查

## 先恢复可操作状态

右键 MacBar 的四格菜单栏按钮，选择“展开全部顶栏图标”。它会展开包括“不显示”在内的图标，不会删除已保存的配置。关闭原生菜单后可使用“重新应用布局”。

## 找不到权限列表里的 MacBar

请先把应用放在固定安装目录并打开一次。系统列表仍没有时，用“+”选择该目录中的 `MacBar.app`。源码构建目录和最终安装目录可能有多个副本，确认授权的是实际运行版本。不要授权裸可执行文件来替代应用包。

## 原样图标不出现，或只有应用图标

默认选择“标准图标”，不捕获屏幕。需要顶部的原生图标和动态文字时，可选择“与顶部一致”并允许 Screen Recording。此时 macOS 会显示捕获提示，且仅在收集栏打开时读取画面。应用未提供有效画面时使用标准图标或上次有效画面，可在设置页和图标悬停提示中查看同步状态。

## 为什么收集栏没有飞书未读数字？

默认模式读取的是应用本身的图标，不会复制顶部菜单栏的数字、状态文字或 Dock 角标。原始画面模式可保留同一个菜单栏窗口内绘制的数字，每 3 秒刷新一次；它没有独立的消息计数接口。若应用把数字画在另一个窗口、离屏后不更新或读取失败，数字可能不出现或停留在上次画面。先确认模式开关已打开、录屏权限显示绿色，再核对顶部原始图标；不能仅凭授权就认定未读数一定同步。目前未完成真实飞书新消息的同步实测。

## 每安装一个应用都需要重新录屏吗？

不需要。MacBar 不要求手工录制每个应用的图标，录屏权限也不是按被管理的应用逐个申请。MacBar 获得授权并选择“与顶部一致”后，新创建的菜单栏图标会自动按全局设置加入并同步。仅安装但未启动、或应用没有提供菜单栏图标时，不会出现；可以先检查该应用自身的菜单栏图标选项。MacBar 不保存截图或视频。

## 为什么显示“MacBar 正在捕捉你的屏幕”？

这是原样模式读取菜单栏窗口画面触发的 macOS 提示，不是自动检测应用所必需的。2.5.1 起默认关闭原样模式，旧版默认状态不会自动沿用。保持关闭即可停止图像捕获；需要时也可在系统设置中撤销录屏权限。诊断摘要中的 `captureRequests` 是进程本次启动以来实际调用图像捕获接口的次数。

## 启动应用后，顶部和收集栏都没有它

先区分三种入口：Dock 中的应用图标、左上角的“文件 / 编辑”等菜单、右上角的状态图标。MacBar 只管理最后一种。普通应用即使正在运行，也不一定创建状态图标，不能据此判断扫描漏掉了应用。

如果确认该应用原本在右上角有图标，请先选择“展开全部”，核对应用自己的状态栏图标开关，再反馈具体版本、显示器组合和复现步骤。现有逻辑会自动发现新创建的状态图标，无需屏幕录制权限。

## 左键打开菜单，没有主窗口

悬停查看动作提示。普通应用左键通过系统重新打开应用；常驻工具保留原生左键。若应用声明 `LSUIElement`，即使它提供主窗口，也可能被识别成面板工具。请在 Issue 中提供应用版本、预期动作，以及直接在顶部点击时的行为；不要仅凭菜单是否出现判断左右键是否被混淆。

## 鼠标或顶部图标反复闪动

先展开全部并关闭原生菜单，再重新应用布局。自动回收连续失败 3 次后会停止，保留任务等待手动操作。请提供是否发生在空闲刷新、点击之后、切屏后或唤醒后，以及显示器数量。不要持续重复点击“重新应用布局”来掩盖无法移动的问题。

## 图标回到顶部后没有恢复

保持目标菜单关闭、松开鼠标并停止移动片刻。仍未恢复时检查设置中的错误提示，再手动重试。应用退出或窗口身份变化后，不会随意用另一个未知窗口替代目标。

## 日志和只读诊断

| 位置 | 内容 |
| --- | --- |
| `~/Library/Logs/MacBar/events.jsonl` | 布局、事件投递、菜单观察和恢复记录；超过 2 MB 轮换 |
| `/tmp/macbar-row.txt` | 当前图标、原样读取状态及左键动作分类 |

源码构建后可运行：

```bash
./build/MacBar.app/Contents/MacOS/MacBar --diagnose
```

该命令只扫描并输出诊断，不移动图标。终端启动的权限归属可能与 GUI 启动不同，不能用它单独判断已安装应用丢失授权。

分享前检查并删除应用名称、图标文字、进程号、窗口标识、文件路径及任何不希望公开的内容。通常只需贴出相关几行、错误时间和复现步骤，不要上传整个诊断目录或桌面截图。
