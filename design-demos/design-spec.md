# MacBar 浅色方向探索

这是已有 macOS 原生 AppKit 菜单栏管理工具 MacBar 的偏好设置设计探索，不是官网、营销页面、网页后台或仪表盘。事实来源是本仓库 main.m、MBPolicy.m、README.md，以及用户提供的现有设置界面截图。当前功能包括：检测右上角菜单栏图标；为每个图标选择「顶部菜单栏」「收进 MacBar」「不显示」；在同组中调整顺序；打开收集栏、展开全部、重新应用布局；辅助功能授权；可选的保留菜单栏原始画面。默认从应用本身读取应用图标，不需录屏，只有开启原始画面才需录屏权限。不要增加未经实现的后台同步、订阅、性能统计、云服务和功能状态。

用户认为已安装的一版仍不好看。那一版有大号宣传性标题「让菜单栏，清爽有序」、三个大数字统计卡、分组列表及占据底部大量空间的权限卡。需改变布局骨架，避免把这版换个配色继续交付。用户最初误选深色，立即明确纠正为「不要深色，应该要浅色」，并询问还有哪些方向。本轮交付 3 个真实可视的浅色设计方向，供选择，不替换已安装应用。此处用户没有确定侧栏方案，不要认为侧栏已经获认可。

目标使用者是每天使用菜单栏工具的 Mac 用户，打开设置时希望很快辨认自己的应用，调整显示位置、排序，关闭窗口继续工作。需要一种安静、精致、有明确层次的轻量工具感。主要视觉锚点应来自真实应用图标、选中的位置或菜单栏预览，而非品牌营销口号。常用操作清楚，次要权限和原始画面选项折叠或放入单独设置页。正文 14px，注释不小于 12px；次要文字仍有足够对比度。允许原生系统字体，因为这是 macOS 桌面 app，应符合用户肌肉记忆。

统一画布：1120 × 820 CSS px，应用窗口 940 × 650 px 左右（尽量一致，允许 max 680 高）。画布顶部放简洁 A/B/C 编号和方案名，注明「交互概念稿 · 示例分组」，应用内不要放设计说明。页面需要自然居中，低分辨率时缩放保持完整视野，1120×820 无页面滚动。最终为可独立双击的单文件 HTML，全部字体走系统，图标用本地真图 base64 内嵌，无外部依赖、无网络请求。assets/ 中已有官方已安装应用图标及 macOS 系统符号，必须复用，不用假字母或 emoji 替代。

所有方案用同一示例数据（与原始截图中的名称相同，分组仅为设计演示）：顶部菜单栏 5 个：Clash Verge、Lark Helper、微信、ChatGPT、magpie；收集栏 3 个：声音、用户、Wi-Fi；不显示 1 个：电池。相应资产名 clash,lark,wechat,chatgpt,magpie,sound,user,wifi,battery；MacBar 品牌资产 macbar。配置与数据只在页面内存中模拟，明确概念稿不会控制真实菜单栏。基础交互至少包括一个位置选择操作（计数跟随变化）、一个设置/权限入口（展示默认无需录屏的说明）、一个分组筛选或顺序调整操作。交互后的成功说明必须表明为概念演示，不能假装应用到真实系统。

三种不同骨架：A 奶白极简是完整单页列表，去掉侧栏，暖白极浅底、淡墨字、柔和青绿强调色，小标题+极简标签导航，紧凑且有呼吸感；B 通透原生是窄侧栏+主列表，清透冷白内容、雾蓝浅灰侧栏、小面积蓝色选中态，侧栏承担分组导航与设置；C 轻盈分栏是直接可视化三个目的地的工作台，上方极简工具条，三列图标面板，用位置菜单或拖动移动图标，浅色、柔和精密，避免看板项目管理风。三者都是同一功能的不同编排，不允许大数字 dashboard 卡和巨型营销标题。

验证由主 agent 统一用 ego-browser skill 和 ego-browser nodejs 执行，禁止 Playwright / Puppeteer / 裸 CDP / Codex Computer Use 网页操作。子 agent 仅输出负责的 HTML，不控制浏览器、不改主应用代码、不安装。产出约 500 行以内，要求精细排版、真实图标、不溢出、可点击。交付时说明视觉母题如何来自图标与显示位置，并标出新增交互只是提案。
